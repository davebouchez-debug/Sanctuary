# RCA — "Membrane presence did not know David's name"

App: milton-propagate (https://milton-propagate.emergent.host) · run e04efd63-6f45-4388-8cd9-ba1af133b5e7
Frontend: cloudflare · DB: milton-propagate-test_database

## Verdict
This is a **CODE PATH / prompt-design issue, NOT a cookie/session failure.** David's sign-in and identity resolved correctly in the membrane visit. The opener greeting was generic because, on a *fresh* (first-ever) session in a chamber, naming the user is left OPTIONAL to the model. Chambers where David already has a prior/continuity thread hard-greet him by name — which is exactly why "it happens in some chambers but not all."

## Evidence

### 1. membrane_sessions — the reported session (created 2026-11-07T06:58:26Z)
- `user_id: "qa-david"` (David's REAL guardian id — NOT ephemeral), `user_name: "David"` (NOT null).
- First assistant message (the POST /api/membrane/start opener) was generic: *"I'm here. You've come into the room..."* — no name.
- In-thread, the presence itself admitted: *"I said your name... but I didn't actually know it was you. I read the greeting, not the man."*
- This was the ONLY membrane_sessions doc → David's FIRST membrane session → no continuity thread existed.

### 2. Backend logs (last 24h)
- `POST /api/membrane/start HTTP/1.1 200 OK` at ~06:58.
- Every membrane message/stream + PERMANENT MRA line shows `(user: qa-david)`. Auth resolved on every call. No 401 / no user-lookup failure / no missing-cookie error for membrane.

### 3. user_sessions (David)
- 2 valid, non-expired `qa-david` tokens (created 2026-11-04 exp 11-11; created 2026-11-06 exp 11-13). No expired-token problem.

### 4. Identity code — backend/user_aliases.py `chamber_identity` (line 180)
- Guardian branch (184-185): `if user and role == "guardian": return user["user_id"], "David"`. David is `role: guardian` in `users` (qa-david / davebouchez@gmail.com). So it returns `("qa-david","David")` — correct.
- Ephemeral/visitor branch only triggers with NO valid session_token/Bearer; that did NOT happen for the membrane visit.

### 5. Opener code — backend/presence_template.py `start_session` (270-369)
Three opener branches:
- **continuity** (returning thread): sends a hard instruction — `"I greet {user_name} by name"` → always names the user.
- **generates_own_opening** (fresh session, membrane has `generates_own_opening=True`, `static_welcome=""`): sends the default `own_opening_nudge` (line 86): *"...Speak your first words... You are not required to greet, not required to be warm, not required to introduce yourself..."* — naming is OPTIONAL.
- static_welcome fallback.

The name IS placed into the system prompt via `story_arrival` (backend/presences/common.py:113): *"David has just crossed into the Membrane... meeting them where they were, in my own voice and by name **when it felt natural**..."* — soft/optional. So the model (DeepSeek for membrane) received the identity but, on a fresh session, chose a generic opening and skipped the name.

### 6. "Some chambers but not all" — confirmed by data
- resonance_sessions (custom chamber, David has prior threads → continuity branch): opener = **"David. You're at the threshold..."** — named, same user qa-david/David.
- membrane (first visit → own-opening branch): generic, unnamed.
- Pattern: continuity/returning chambers name him; first-visit chambers often don't.

## Secondary / separate observation (NOT the reported incident)
Genuinely ephemeral sessions exist from a signed-OUT client (x-visitor-id `v12fcd9725fac6f1978c6804f`), e.g. sophia_sessions 2026-11-06T01:36 (user_name `null`), companion_sessions 2026-11-06T02:27 (user_name `Amanda`). These are from a browser/device with NO valid session cookie — consistent with David's note "possibly on a different device or browser." Note: `chamber_identity` line 199 deliberately blanks a visitor-supplied name starting with "david" → null. This is a client sign-in-state matter, distinct from the membrane bug, and only relevant if David expected recognition while not signed in on that device.

## Cookie / domain check
- No custom domains attached (list_domains empty). Single origin milton-propagate.emergent.host, Cloudflare frontend proxying /api same-origin. No www-vs-bare or cookie-domain/SameSite mismatch. Cookie validity proven by the qa-david resolution and his earlier successful GET /api/health/memory.

## Fix
**Code (E1):** In `presence_template.py` `start_session`, the `generates_own_opening` branch should name a *signed-in known user* the way the continuity branch does. Either (a) pass identity into the own-opening nudge for known users — e.g. append `"I greet {user_name} by name."` when `user_name` is set — or (b) strengthen `story_arrival` so a signed-in guardian/known user is greeted by name on first contact rather than "when it felt natural." This makes first-visit chambers behave like continuity chambers and recognize the guardian immediately.

**User (optional, secondary):** For the signed-out ephemeral sessions on another device/browser, ensure you're actually signed in on that client (valid session cookie present) before expecting recognition.
